## 本研修の設計原理（講師用レジュメ）

「校務利用から教育利用へ」の裏には、**教育で使う前に校務で生成AIに慣れる**という隠れた目的がある。だが対応表を作ると、校務で育つ慣れ(A)と教育に必要な慣れ(B)は一部しか重ならない。本研修はAを前半で圧縮再生産し、Bを後半で追加インストールする。**B6だけは校務の手癖の逆向き矯正**。

| # | 慣れ | ワーク | 使うアプリ |
|---|---|---|---|
| — | ウォームアップ+前回のおさらい（@エージェント利用） | 0 | **カレンダー**（共有・全員編集）+Gemini **@アプリ呼び出し** |
| A1 | 対話で育てる | 1 | **ドキュメント**+Geminiサイドパネル |
| A2 | 型で頼む | 2 | **Gemini**→ドキュメントにエクスポート（発展: フォーム/NotebookLM） |
| A3 | 出力を疑う | 3 | **ドキュメント共有**+コメント・提案モード |
| A4 | 個人情報を入れない | 4 | **スプレッドシート**+Geminiサイドパネル |
| A5 | 出力は下書き、決定は自分 | 5 | ドキュメント/スプシの**変更履歴** |
| B6 | 答えを出させない使い方 | 6 | **Gemマネージャーで自作**（解体新書つき）vs Geminiアプリ |
| B7 | 目的で使い分ける | 7 | **フォーム**（リアルタイム投票→回答グラフ投影） |
| B8/B9 | 失敗に慣れる/出典まで行く | 8 | Gemini→**NotebookLM**（町資料ソース）+**AIモード** |
| B10 | 記録と明示 | 9 | **フォーム「AI利用ログ」**→スプシ蓄積 |
| B11 | 手続きを確認する | OK/NGクイズ | **フォームのテストモード**（即時採点+解説） |
| B12 | 待つ（予想→AI→ズレ） | 全ワーク共通 | 紙 or ドキュメント冒頭に「自分の案」行 |

- Workspaceで組む効用: ①ワーク自体がアプリ操作の練習を兼ねる（共有・コメント・変更履歴・フォーム作成は校務スキルそのもの）②成果物が全部ドライブに残る＝研修後そのまま使える③フォーム集計で研修自体がデータになる（午前の「学びのモニタ」と同じ構造を教員自身が体験する）

### ワーク1〈A1 対話で育てる〉ドキュメント×サイドパネルで学級通信

**アプリ操作**: ドキュメント新規作成 → 1行目に自分の書き出し案（B12）→ 右上✦でGeminiサイドパネルを開く → 依頼 → 「挿入」。

```
保護者向け学級通信の一段落を150字で書いて。
2学期開始のあいさつ。夏休み明けの子どもの生活リズムを気遣う内容。
ですます調、あたたかい語り口。
```

挿入した文に対して、**サイドパネルで追加注文を3連発**（そのまま採用は禁止）:

```
もっと短く、120字くらいに。
沖縄の9月の季節感をひとこと入れて。
最後の一文を、保護者への具体的なお願いに変えて。
```

- 講師の声かけ: 「1回目の出力はたたき台。**同じ画面の中で育てる**のがサイドパネルの使い方です」
- 副産物: このドキュメントがそのまま2学期の通信の下書きになる（ドライブに自動保存）

### ワーク2〈A2 型で頼む〉Geminiで型発注→ドキュメントにエクスポート

**アプリ操作**: Geminiアプリで型の6行（役割/ゴール/前提条件/プロセス/形式/例）を使って発注 → 出力下の**共有アイコン→「ドキュメントにエクスポート」**でドライブに保存。

```
以下に示すタスクを実行して。
役割: 小学◯年生（中学◯年生）を教えるベテランの◯◯科教師
ゴール: 「◯◯」の単元の3択クイズ5問
前提条件: 誤答の選択肢は、子どもがやりがちな勘違いをもとに作る
形式: 問題→選択肢→正解→解説の順。解説は子どもに話す口調で
```

- **発展A（環境があれば）**: Googleフォームを新規作成→設定で「テストにする」→Geminiのフォーム作成支援でクイズを下書き→自己採点テストとして配信できる形に
- **発展B（コアメンバー向け予告）**: NotebookLMに教科書・単元プリントをソースとして入れ、「このソースだけからクイズを5問」→ **教材に接地したクイズ**（Geminiの自由生成との違い＝ハルシネーション対策の構造）

### ワーク3〈A3 検証の目〉ドキュメント共有+コメントで検品

**アプリ操作**: ワーク2でエクスポートしたドキュメントを**隣の人と相互共有**（共有→相手のアドレス→「コメント可」）→ 相手のクイズを3観点で検品し、**怪しい箇所を選択→コメント🔴**を付ける。

- [ ] 事実の誤りはないか（数字と固有名詞から疑う）
- [ ] 言葉のレベルは対象学年に合っているか

- 副産物: 共有・コメント権限の操作はそのまま校務スキル（指導案検討・行事案の回覧と同じ動線）

### ワーク4〈A4 匿名化の手癖〉スプレッドシート×サイドパネルで所見素案

導入クイズ（30秒）: NG依頼文「2年1組の比嘉◯◯さんの所見を書いて…」→ どこがダメ?（実名）→ **名前を消すのではなく、最初から事実メモに変換して入れない**。

**アプリ操作**: 共有ドライブのテンプレ「所見素案.gsheet」をコピー（A列=匿名番号、B列=事実メモ、C列=素案）→ B列に事実メモを1行入力 → **スプシのGeminiサイドパネル**に依頼:

```
B列の事実メモから、通知表所見の素案を100字で2案作って。
保護者が読んで情景が浮かぶ、具体で短い文で。
事実メモ: 係活動（配り係）を1学期続けた/算数の「割合」でつまずいたが
放課後に自分から質問して克服/友だちへの声かけがやさしい
```

## Part 3. ギャップの慣れをインストールする（15:10〜16:10 / 60分）

### ワーク6〈B6 出させない使い方〉「深まる問いGem」を自分で作る — 解体新書つき（18分）

Gemは配らない。**全員がその場で作る**。自作したAIは中身を説明できる — 子どもに配るとき説明責任が果たせるのは、作った人だけ。

**手順1: 解体新書（5分・講義）** — プロンプト集に指示全文（[06](06_thought_scape_training.md)のWork C）を掲載し、5つのブロックの「なぜ」を読み解く:

| ブロック | 中身 | なぜそう書くか |
|---|---|---|
| 人格と使命 | 「問いを深めることだけをする存在」 | Gemの性格は最初の1文で決まる。使命を1つに絞るほど壊れない |
| 絶対ルール | 答えない/褒めない/3行以内/言い換えすぎない | 答えない=虚無防止。**褒めない=子どもがAIの機嫌を取り始めるのを防ぐ**。3行=読む気が続く |
| 再帰ループ | 鏡→前提→二枚の扉→深さ+1 | 鏡=聞いてもらえた感。前提=当たり前を照らす。**扉を選ぶのは常に人間**=深まりの主語を本人に残す |
| 塩梅の監視 | 返事が短くなったら具体の扉だけ | 抽象度の上げすぎ=虚無への転落を自動検知 |
| 終了条件 | 問いの系譜+「捉えて離しませんか?」 | 旅の地図を渡して終わる。永遠に続けない |

**手順2: 自作（5分）** — Gemini→**Gemマネージャー→「Gemを作成」**→名前「深まる問いGem」→指示欄にプロンプト集から貼り付け→保存。

**手順3: 二刀比較（7分）** — 自分が苦手な話題（割合、標準偏差、季語…）を、①Geminiアプリに「◯◯がわかりません。教えて」、②いま作った自分のGemに「◯◯って、そもそも何なんだろう?」— **同じ話題を両方に投げて3往復**。終了時の「問いの系譜」はドキュメントに保存。

**手順4: 1か所だけ改造（3分）** — 指示文のどこか1行を自分用に書き換える（語彙をひらがなに/深さ上限3に/自分の教科の例を足す）→ **これが「自分の教科版Gem」の種**。改造できる=中身を理解した証拠。

- ペアで30秒: 「①と②、授業の何分後に子どもの手が止まるか」
- 講師のまとめ: 「①はStep2（授業準備）の正解。**Step4では②に持ち替える** — これが向き直し」
- 落とし穴: Gemに「答えを教えて」と頼み込む人が必ず出る → それが教材。「いまの"おねだり"を、子どもは100倍します。だから絶対ルールは指示文に書いておくんです — 皆さん、いまそれを自分で書きましたね」

### ワーク7〈B7 目的で使い分ける〉フォーム投票×回答グラフ（6分）

**アプリ操作**: 事前作成のフォーム「出させる? 出させない?」（6場面・各3択: 出させる/出させない/AIを使わない）に全員が回答 → **回答タブの円グラフを投影** → 割れた場面から議論。

1. 計算ドリルの答え合わせ →使わない（解答集で足りる。AIは計算を間違える）
2. 自由研究のテーマ決め →出させない（出させたら"やらされ探究"の再生産）
3. 読書感想文の下書き →出させない（虚無の典型。たたき台は学校のねらいと規程次第=△）
4. 実験計画の穴探し（つっこみ係）→出させてよい（指摘という情報は演算の入力）
5. 調べ学習の年表整理 →出させてよい・出典裏取りとセット
6. 苦手な子向けの類題を教師が作る →出させてよい（Step2の王道）

- 判定基準スライド1枚: 「**この時間のねらいは再現か、拡張か**」「**出力は誰の成果物になるのか**」
- 「正解の暗記が目的ではない。**円グラフが割れた場面こそ職員室で話す価値がある** — このフォーム、そのまま校内研修で使ってください」

### ワーク8〈B8 失敗に慣れる+B9 出典まで行く〉Gemini→NotebookLM→AIモードの三段裏取り（12分）

地元は先生方が専門家 — 検証できる題材でAIの限界を安全に体験する。

**手順1**: Geminiに書かせる（わざと数字を要求してエラー率を上げる）:

```
嘉手納町と周辺地域の歴史・地理・文化について、中学生向けの解説を300字で。
年号・人口などの数字を3つ以上入れて。
```

**手順2**: 講師が事前作成した**NotebookLM共有ノートブック「嘉手納町 公式資料」**（町公式サイト・町勢要覧・観光資料等をソース化）を開き、Geminiの解説文を貼って照合:

```
次の解説文の主張を1文ずつ、ソースと照合して。
ソースで確認できた=🟢、ソースと食い違う=🔴、ソースにない=❓で判定し、
🟢には引用を付けて。
```

→ **引用番号をクリックして原文まで行く**（NotebookLMはソースに接地して引用を返す — 「出典まで行く」がワンクリックになる）

**手順3**: ❓（ソースにない主張）だけ、Google検索の**AIモード**でウェブ裏取り:

```
「（AIの主張をそのまま貼る）」は本当ですか。出典つきで教えて。
```

- 全体で🔴の実例を2つ拾う → 「これを**授業中に子どもと一緒にやる**のが『先生の失敗の授業化』。前日に一度試す（リハーサル）だけで、教室では余裕をもってだまされられます」
- 構造の言語化: **Gemini=接地なしの生成/NotebookLM=手元資料に接地/AIモード=ウェブに接地**。三つの道具の違いが、そのまま子どもに教える情報の授業になる
- 落とし穴: 🔴が見つからない班 → 「**🟢に根拠を付けるほうが偉い** — 検証は粗探しではなく裏取り」

### ワーク10〈EBPMの樹〉振り返りが、明日の授業を変える（12分）

**講義: EBPMの樹（3分）** — 全体スライド「EBPMの樹」（根=業務デジタイズ/幹=データ統合/枝=可視化/葉=パーソナライズ）を学校サイズに縮約する:

| 樹 | 本家（Google Cloud） | 今日から育てられるミニチュア |
|---|---|---|
| 葉 | 個別データで教育活動をパーソナライズ | **明日の授業の一手**（冒頭5分の手当て・再挑戦問題・声かけ） |
| 枝 | BigQuery・Lookerで可視化 | **Workspace Studioが毎日17:00にGemini分析→Chat配信** |
| 幹 | スプレッドシート・Cloud SQLで統合 | **フォーム回答がスプシに自動蓄積** |
| 根 | Google for Educationフル活用でデータ蓄積 | **帰りの会90秒の振り返りフォーム**（[08](08_reflection_form_design.md)） |

**エビデンス（2分）** — なぜ「振り返り→授業改善」に張るのか:

- ハッティ（2003）: 学力の分散の約50%は生徒自身。それを除けば、**教師は学校側で働きかけられる最大級の影響源（約30%）**
- 核心の一文（Hattie 2012）: **「最大の効果は、教師が自らの指導の影響の学び手になるときに生じる」**（Know thy impact）。形成的評価とは「コックがスープを味見する」こと — 味見せずに出す料理はない
- Gates財団METプロジェクト: 約3,000人の教員調査で、**生徒質問紙は授業観察より一貫して学力の伸びを予測** — 子どもの声は授業改善の信頼できるデータ源
- ⚠️ 留保: ハッティの個々の効果量は版により大きく改訂され（例: 集合的効力感1.57→1.34）方法論への批判もある。**数値を絶対視せず「教師の授業改善は効く領域だ」という地図として使う**（[01](01_evidence.md)）

**デモ（3分）**: 午前のコア研修と同じ自動化フローの実物 — 架空データで、17:00にGoogle Chatに届く「担任向け1分ブリーフィング」（⑤例外が最上部・🔴🟡🟢つき）を見せる。

**ディスカッション（4分）**: **「17:00にこれが届いたら、あなたは明日の授業の何を変える?」**

- 呼び水: 冒頭5分の手当て/誤答者だけの再挑戦問題/ペアの組み替え/⑤の子への朝の一声/「今日の学び方」で出た方略を学級に紹介
- グループで話し、1つだけ全体共有
- 締め: 「**樹は葉（授業の一手）まで届いて、初めて教育になる。枝（Chat配信）で止まったら、それはただの通知**。導入の相談は各校コアメンバー+教委へ」

### ワーク9〈B10 記録と明示〉AI利用ログの「フォームを作ってみよう！」（6分）

ログのフォームは配らない。**全員がその場で作る**（Gem自作と同じ思想 — 設問を自分で書けた人は、何を記録すべきかを理解した人）。進行サイトに設問例を掲示し、見ながら各自作成。

**アプリ操作**: Googleフォーム新規作成 → タイトル「AI利用ログ」→ 設問4つを自分で作る:

1. どのアプリで使った?（ラジオボタン: Gemini/自作Gem/NotebookLM/AIモード/サイドパネル）
2. 何を入力した?（段落・要約でよい）
3. 採用したもの（段落）
4. **捨てたものと、捨てた理由**（段落・**必須に設定**）

作れたら、今日のワーク6〜8の利用を自分のフォームに1件記録してみる（回答→スプシ自動作成まで確認）。

- 「④を必須にするのが設計の核心。『決めたのは自分』の証拠であり、子どもの成果物へのAI利用明示（文科省ガイドラインの『やりとりの過程の添付』）の実務形」
- 持ち帰り: このフォームの学級版が、2学期の子どもの探究ノートの標準装備になる。**フォームの設問設計＝「何を記録させるか」の教育設計**そのもの — 回答が集まればスプシが職員室・学級の共有知になる

### OK/NGラインクイズ〈B11 手続きを確認する〉フォームのテストモード（6分）

**アプリ操作**: 事前作成のフォーム（設定→テストにする・回答後に解説表示）に全員回答 → 即時採点と解説が各自の画面に出る → 割れた問だけ全体で議論。

| 行為 | 判定 |
|---|---|
| 学級通信の誤字チェックをAIにさせた | ○ |
| 所見の素案をAIに作らせ、自分で直して確定した | ○（ワーク4+5そのもの） |
| AIが挙げた参考図書を、現物未確認で学級だよりに載せた | ×（実在確認 — 幻覚文献） |
| 子どもの作文を実名のまま貼り付けて添削させた | ×（事実メモ化・匿名化してから） |
| 読書感想文の宿題で、子どもがAIに下書きさせた | △（**「学校のルールとねらいを確認する行動」が正解**） |
| 授業中にAIの答えが間違っていたので、子どもと一緒に検証した | ◎（ワーク8の実戦形） |

- 締め: 「ルールはAIを禁止するためでなく、**先生と子どもの成果物が疑われたときに守るため**にある」
- 副産物: 「テストモード+解説表示」の操作自体が、2学期の小テスト運用（ワーク2発展A）の練習
